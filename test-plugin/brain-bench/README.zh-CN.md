# Brain 与真实 POI 验收

本工具只在独立的新建超平坦测试世界中使用。启动属性 `lattice.brainPoiBenchmark=true` 才注册夹具命令。它会在测试世界搭建 25 组围栏，每组有 80 名成年村民、80 张床、80 个木桶和 3 口钟；村民通过正常 AI 认领 POI，不注入记忆或睡眠状态。

当前实现已移除 memory-index/expiry-index 结构及对应启动属性；验收仅比较统一的 Brain 行为实现，不再反射旧索引字段。

## 预登记协议（2026-10-11）

本次只验收已有的 memory-index、expiry-index。§10.1 的 Gate 合并扫描、declarative opcode、sensor 共享或降频没有因此获得正确性认可或被算作已经实现。

先执行最多两次 off pilot，核实可达性及下列功能条件，pilot 不进入性能样本。夹具有效后冻结 JAR、插件、配置、JFC 和协议 SHA-256。正式实验为 16 个独立 JVM，四个区组的执行顺序依次为：

1. off、memory、both、expiry
2. memory、expiry、off、both
3. expiry、both、memory、off
4. both、off、expiry、memory

每轮新建世界，16 个真实协议 bot；runner 只在 disposable runtime 把村民 activation range 改为 0（始终激活），模板保持原样。POI 搜索半径 48，lobotomize=false。世界与布局 seed 固定，但不声称 AI 随机轨迹完全相同。测试时不得并发构建或运行其他计时任务。JFR 在预热前启动；初始认领固定 2000 tick 且不少于 90 秒。依次切换 WORK=6000、MEET=10000、REST=14000，每阶段使用 `schedulingbench start 1000 1000`，保存全部 1000 个准备 tick 和 1000 个正式 tick。正式窗口不做 census，不修改 POI 或世界时间。

每 JVM 主 CPU 指标为三个正式窗口同窗进程 CPU 的和；主 p99 为三个窗口共 3000 tick 的 nearest-rank 分位数。另外逐阶段报告 p99、全部准备点和严格 >15/25/50/100ms 计数。统计独立单位是 JVM，不是 tick。

功能门槛：2000 个目标村民全部有效、成年、AI 开启、位于对应围栏且处于 entity-ticking 区块；16 bot 全程驻留。WORK 后有效 JOB_SITE 至少 95%、本阶段实际工作至少 90%；MEET 后有效 MEETING_POINT 至少 90%、每组均有村民接近自己的钟；REST 后有效 HOME 至少 95%、本阶段实际睡眠至少 90%。所有位置记忆必须指向正确类型，POI 占用不超容量，床和工作站无重复认领。记录 POI 票据与记忆的差异、潜在工作站、实际睡眠、原生资格计划和索引有效数。仅测试世界取消 VILLAGE_DEFENSE 铁傀儡生成并计数，生成尝试成本仍计入。

对三个候选分别计算四个区组相对 off 的 CPU、p99 log ratio 及 p99 毫秒差，使用配对 t 区间，单侧置信度 98.33%（三候选比较校正）。n=4 的分布假设和不确定性必须明确报告。

支持本场景 opt-in 必须同时满足：

- 正确性及功能全部通过；CPU 点估计下降至少 3%，上置信界小于 0%。
- 整体 p99 上置信界不超过 +3% 且不超过 +0.5ms。
- 每阶段 p99 上置信界不超过 +5% 且不超过 +1ms。
- 不出现两个以上区组中候选比 off 每 3000 tick 多至少 3 次 >50ms 的情况。

正确性或功能回归、有证据排除 3% CPU 收益、或尾部下界超过容忍量时，有证据维持关闭；区间跨越门槛时，证据不足以支持开启。不得以“未显著变坏”冒充非劣，也不因结果不理想追加样本。技术故障保留全部证据，最多补跑一个完整区组；候选功能失败不能当技术故障删掉。off 也无法达到功能门槛则夹具无效，应先修正夹具，不能生成性能结论。

本实验最多支持已验证场景的 opt-in。全局默认仍为 false；没有混合负载和低负载的独立证据，不自动晋级默认值。JFR 栈样本、分配和暂停仅解释原因，不代替 CPU。§10.1 未覆盖项按统一分类报告，嵌套栈不重复累加收益。
